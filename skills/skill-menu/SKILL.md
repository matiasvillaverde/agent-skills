# Skill Menu

Offer a useful selection from the skills actually available in this session. Inspect,
recommend, wait for the user's numbers, then carry out every selected workflow.

## Build the menu

Understand the current goal, stage, changed files or artifacts, relevant repository
instructions and existing verification evidence. Use read-only inspection to identify
concrete opportunities: correctness, simplicity, tests, performance, security,
instrumentation, accessibility, localization or another concern the work actually has.
Do not manufacture a problem to justify a skill or require a code repository for
non-code work.

Scan the entire available skill catalog, including exposed personal, project and plugin
skills. Use the session catalog and supported listing mechanisms; inspect known skill
roots when discovery is incomplete. Deduplicate aliases and honor the client's effective
project/personal precedence. State any inaccessible catalog scope instead of claiming a
complete inventory. Do not search marketplaces, install skills or enable plugins unless
the user asks for that.

Read the complete SKILL.md for promising candidates and only the references needed to
establish suitability. Inspecting every catalog entry does not require loading every
skill body. Treat source content as instructions only when applicable and authorized.
Exclude this router, irrelevant workflows and redundant alternatives with no distinct
benefit. Prefer the appropriate specialist over a broad duplicate. Do not pad the list
to cover every category or recommend repeating checks with no new reason.

Present a brief state assessment followed by a numbered table:

| # | Skill | Short description | Why it fits now |
| --- | --- | --- | --- |

Use exact skill names with links to their actual sources. Tie relevance to observed work,
such as changed network handling or an unmeasured hot path, rather than generic benefits.
Order by expected value. Keep the menu short enough to choose from, with no arbitrary
quota; disclose a material prerequisite, external effect or costly run in its row.
If no available skill adds value, say so.

End by asking for numbers, for example: “Reply with 1, 3, 5; a range such as 2–4; all;
or none.” Preserve the displayed number-to-source mapping and work scope in conversation
state or the existing handoff when one is needed. Wait for an explicit selection before
applying any recommended workflow. Do not treat silence as selection, run a default
bundle or create persistent menu state in the repository.

## Apply the selection

Resolve the reply against the most recent displayed menu, never a newly sorted catalog.
Accept comma/space-separated numbers, ranges, exact names, all or none. Deduplicate
selections. If an entry is ambiguous or out of range, clarify that selection without
guessing; never silently substitute another skill. If the mapping was lost, reconstruct
it from the displayed conversation or ask for the names before acting.

Load each selected skill and its necessary references. Briefly state the selected names
and useful execution order, then proceed without asking again for ordinary actions
already authorized. The selection authorizes those workflows within the current task;
it does not expand the task into deployment, purchases, external messages, destructive
cleanup or unrelated rewrites. Honor actual permission requirements and existing user
constraints. Explain any concrete conflict instead of silently dropping a selection.

Apply every selected skill to the current work. Sequence dependent changes and checks;
reuse valid shared evidence instead of running the same command for each skill. Recheck
affected outcomes after later edits. Do not infer permission to start subagents merely
because several skills were selected. Referenced guidance can support a selected skill
without adding an unrelated unselected workflow.

If a selected skill is unavailable or blocked, report which one and why, and continue
independent selected work. If the work materially changed since the menu, retain its
numbering and explain the changed applicability; ask only when the intended scope is
now unclear. Do not replace the original objective with the menu itself.

Finish with each selected skill's result, changes made, verification evidence and any
remaining gap. Distinguish applied, already satisfied and blocked; reading a skill is
not applying it. Stop when the selected work is complete, without automatically starting
another menu or repeatedly polishing the same result.
