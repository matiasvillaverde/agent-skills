# Go observability and finishing checks

Research checked 2026-11-13. Inspect go.mod, toolchain declarations, lock/dependency state, existing handlers, and deployment lifecycle. log/slog requires Go 1.21 or later; retain a supported existing logger on older projects instead of forcing an upgrade. Check current package docs against the project’s actual Go release before using newer APIs.

Prefer existing structured records with stable event names, category/component, terminal outcome, duration when useful, and correlation fields. slog JSONHandler and TextHandler are both structured formats; do not add a formatter package simply to require JSON. Use Logger.With/WithGroup for small common attributes, not a new wrapper for every module. Keep event vocabulary bounded and avoid request IDs, raw URLs, or error strings as metric labels. See [slog](https://pkg.go.dev/log/slog).

The main application owns handlers, destinations, defaults, and severity/category configuration. Libraries should use the existing injected/default logger convention without calling SetDefault or installing handlers during init. HandlerOptions.Level can reference a LevelVar for concurrent runtime severity changes; a fixed Level is not dynamically adjustable. Category is an attribute unless the chosen handler/configuration actually filters it. Reuse existing category controls rather than introducing a routing framework. Go’s [structured logging explanation](https://go.dev/blog/slog) explains the handler/attribute design.

Context-aware methods let handlers obtain request metadata, but slog does not automatically invent or attach trace IDs. Propagate the existing context, explicitly attach approved identifiers, or use the installed integration. Cancellation of that context does not itself suppress a log entry. Keep context values request-scoped, with collision-resistant keys rather than raw string keys; do not use context as a bag of optional configuration. Return/wrap an error with useful context and let its handling boundary log it once. Distinguish ordinary caller cancellation from a real timeout or service failure using the operation’s contract.

Allowlist attributes. LogValuer can provide a safe representation of a sensitive type, while an existing handler’s ReplaceAttr can remove or transform fields; neither makes arbitrary object/error dumping safe. Do not log credentials, whole payloads, or query strings. Check Enabled before expensive debug-only argument construction; ordinary arguments are evaluated before the logging call. Use LogAttrs or other allocation optimizations only when measurement identifies the logging path as relevant.

Bound diagnostic sampling/rate-limiting state and preserve a useful suppression count. Do not copy a catalog’s “sample every record first” pipeline into a stream containing required audit records. Audit events have an independent retention/delivery policy and must not disappear under a diagnostic level switch; [OWASP](https://cheatsheetseries.owasp.org/cheatsheets/Logging_Cheat_Sheet.html) distinguishes these purposes. Batch/network handlers need their actual documented flush/close lifecycle; slog itself has no universal shutdown method. Stop new work, finish/cancel workers, then flush within the application’s budget. Do not pass an already-canceled request context to an exporter when its contract requires time to drain.

Always release cancel functions and make goroutines observe shutdown rather than detaching work with context.Background merely to silence cancellation. See [context](https://pkg.go.dev/context). After the feature, exercise relevant empty/error input, network refusal, timeout, retry exhaustion and cancellation. Repeat operations and shutdown to look for leaked goroutines, connections or unbounded queues; inspect the emitted outcome and duplicate request count.

For resource-sensitive changes, compare the same representative workload before and after. Use [Go diagnostics](https://go.dev/doc/diagnostics): CPU/heap profiles for expensive work and retained allocations, goroutine/block/mutex evidence for suspected waiting or leaks, and execution tracing when scheduling is the question. Profilers add overhead and may interfere with each other. Keep diagnostic endpoints restricted to the existing debug surface, not a new public route. Report measurements and limitations, and keep only tests that protect concrete behavior.
