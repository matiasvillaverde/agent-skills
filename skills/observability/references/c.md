# C observability and feature verification

Evidence checked 2026-11-13. Identify the compiler and optimization flags, target OS/libc, logging backend, collector version, ownership conventions, and threading model first. This reference covers POSIX logging and optional systemd integration; it does not require either on unsupported targets. Keep the existing platform adapter and let the executable own configuration. Confirm APIs in the deployed version rather than copying a modern Linux example into embedded, Windows, or older systems. [POSIX syslog](https://pubs.opengroup.org/onlinepubs/9799919799/functions/syslog.html), [systemd journal API](https://www.freedesktop.org/software/systemd/man/latest/sd_journal_send.html)

Emit stable operation/outcome events with explicitly encoded fields at useful boundaries. Keep detailed investigation at configurable component levels, bounded in volume; aggregate hot-loop activity. Preserve error categories and correlation without putting raw payloads, credentials, or arbitrary user values into format strings. `syslog` priorities and `setlogmask` provide runtime filtering, but `setlogmask` is process-wide: a library must not silently change another component's policy. `openlog` may retain its identity pointer, so that storage must remain valid. With journald, use its field API when appropriate instead of pretending free-form text is structured data. [syslog](https://pubs.opengroup.org/onlinepubs/9799919799/functions/syslog.html), [Journal fields](https://www.freedesktop.org/software/systemd/man/latest/sd_journal_send.html)

Ordinary function arguments are evaluated before the logging function can reject a record. Check the supported level predicate before expensive formatting, allocation, serialization, or diagnostic traversal. Distinguish compile-time removal from runtime thresholds: the latter cannot recover calls compiled out. Do not hide necessary state changes inside logging arguments. Preserve available format-string checking, use literal format strings with separately supplied values, and cap field sizes. Changing a runtime logging threshold should not require invasive abstractions or alter program behavior.

Treat logging as I/O with an explicit blocking, allocation, and failure budget. If an existing asynchronous backend is necessary, bound its queue and document buffer ownership, backpressure or loss, drop counters, ordering requirements, and shutdown. `syslog` returns no delivery acknowledgment. Journal calls returning success do not establish durable audit storage; the documented API even succeeds without delivery when the journal socket is absent. The collector can also discard excess records and rotate retained files. Inspect its rate limits and storage limits instead of disabling them universally. [syslog](https://pubs.opengroup.org/onlinepubs/9799919799/functions/syslog.html), [Journal delivery semantics](https://www.freedesktop.org/software/systemd/man/latest/sd_journal_send.html), [journald limits](https://www.freedesktop.org/software/systemd/man/latest/journald.conf.html)

Check each API's error convention. Save `errno` immediately after an operation reports failure, before cleanup or formatting changes it; successful calls do not make `errno` meaningful. Preserve the original failure while releasing resources once, and add context at the responsible boundary. Do not log the same failure at every return. Ordinary stdio and allocating/locking loggers do not belong in signal handlers. Use only a verified asynchronous-signal-safe crash path; journal `sendv` has a specific documented guarantee that formatted journal calls do not share. [errno](https://man7.org/linux/man-pages/man3/errno.3.html), [Signal safety](https://man7.org/linux/man-pages/man7/signal-safety.7.html), [Journal safety](https://www.freedesktop.org/software/systemd/man/latest/sd_journal_send.html)

Audit events need their own actor/action/target/outcome contract, access and retention rules, and explicit failure handling. Sampling and diagnostic level changes must not erase required audit records. Paging should reflect actionable user-impacting symptoms, not every error-priority message. [OWASP logging](https://cheatsheetseries.owasp.org/cheatsheets/Logging_Cheat_Sheet.html), [Google SRE alerting](https://sre.google/sre-book/monitoring-distributed-systems/)

Verify the changed operation with a few relevant allocation, short-I/O, disconnect, timeout, or cancellation failures. Check descriptor/buffer release and bounded requests. Use sanitizers for correctness separately from production-speed measurements. Compare optimized builds with explicit warmup; inspect live allocations across repeated completed work rather than infer leaks from RSS alone. Profile the selected process for a bounded duration, accounting for overhead and sensitive captures; do not loosen host security globally. [AddressSanitizer](https://clang.llvm.org/docs/AddressSanitizer.html), [Benchmark controls](https://google.github.io/benchmark/user_guide.html), [Heap profiling](https://valgrind.org/docs/manual/ms-manual.html), [perf security](https://www.kernel.org/doc/html/latest/admin-guide/perf-security.html)
